# Completed work: 2026-10-22 to 2026-10-22

Archived from `COMPLETED.md` at the 2026-10-22 Mega & Alt-Form
Representation milestone boundary (the milestone's four legs, all shipped
the same day). See `docs/postmortems/mega-alt-form-representation.md`.

**[Mega & Alt-Form Toggle State] — Leg 1** (2026-10-22): Added
`usePokemonFormToggle`, a shared per-roster-slot toggle for the form
currently displayed in place of a Pokémon's stored base form (a Mega
Evolution, or a stat-only forme like Aegislash Blade/Shield) - a
module-level store (subscribed to via `useSyncExternalStore`) rather than
persisted/synced state, since Mega Evolution and Blade/Shield only happen
in-battle. Foundation for Legs 2-4 of the Mega & Alt-Form Representation
milestone and the separate Type Matchup Rework milestone. See commit
de36abf.

**[Mega Team Card Flip] — Leg 2** (2026-10-22): A roster slot's held Mega
Stone now shows a small toggle badge next to the item slot; toggling it (via
Leg 1's shared `usePokemonFormToggle` state) flips the team card's ability
capsule/stats grid/type badges to the Mega's own values, while the existing
always-on Mega sprite swap stays untouched. `useMegaSprite.ts`'s per-slug
PokeAPI fetch now also surfaces the Mega's types/base stats (same response
it was already fetching for the sprite id); the ability override is sourced
from `config/megaAbilities.ts`'s existing forced-ability table. The ability
capsule's click target is unchanged - it still edits the real stored
`showdownData.ability`; the override only changes what's displayed while the
flip is active. See commit 39d56af. Follow-up the same day: replaced the
toggle badge's placeholder "M" glyph and the shiny corner badge's unicode
emoji with Showdown's own `/sprites/misc/mega.png`/`shiny.png` icons. See
commit ddfe933.

**[Aegislash Form Toggle in Team Builder] — Leg 3** (2026-10-22): Added a
Blade/Shield toggle badge to the team builder card's own sprite box
(`AegislashFormToggleBadge.tsx`, shown only for Aegislash), wired through
Leg 1's shared `usePokemonFormToggle` state the same way Mega's toggle is -
defaults to Shield (the stored forme) on a fresh add. Ability stays Stance
Change and typing stays Steel/Ghost in both formes, so only stats change
there - Blade's base stats are derived from the stored Shield stats via
`utils/aegislashForme.ts`'s Attack<->Defense/Sp. Atk<->Sp. Def swap (the
real in-game forme-change rule) rather than a second hardcoded stat table,
so they can't drift from the stored value. See commit 64edf44. Follow-up
the same day, after live feedback that the sprite should flip too: reused
`useMegaSprite.ts`'s generic PokeAPI-slug fetch (already built for Mega
forms, which live at their own distinct PokeAPI id the same way
Aegislash-Blade does) to fetch Blade's own sprite, now shown (static and
animated) only while the toggle is actively pointed at Blade - unlike
Mega's sprite, which stays always-on whenever the stone is held regardless
of the stats toggle, since Aegislash's forme isn't item-driven. See commit
1d7d83c.

**[Battle Log Mega-Evolved Note] — Leg 4** (2026-10-22): RecordMatchForm
had no way to set `Battle.megaEvolvedIds` (it existed on disk already, left
over from the archived live-logging flow, but the form just hardcoded it
to `[]`). Added one Mega-toggle control, reused on both the player and
opponent roster tiles via `BroughtToggleTile`'s existing `trailing` slot,
that marks/unmarks a Pokemon as Mega Evolved - marking one clears any
other mark already set on the same side, matching the real one-Mega-
per-side VGC rule (pure toggle logic split into
`utils/battleMegaToggle.ts` so it's unit-tested without React).
`PastBattlesList`'s saved-match summary now shows a small "Mega" badge,
tooltip naming which Pokemon, whenever a battle has at least one mark.
Live-verified via `run-desktop`: recorded a disposable test battle marking
a player-side Pokemon Mega Evolved, confirmed the badge/tooltip in the
summary list, then deleted it and confirmed on a fresh reload that no
stray data remained. See commit 0961243. Follow-up the same day, after
live feedback that this first pass was too permissive (any Pokemon could
be marked regardless of whether it can actually Mega Evolve, no X/Y/Z
form distinction, no sprite swap): replaced the plain toggle with
`resolveOpponentMegaControl` (`config/megaEvolution.ts`) - hidden for a
non-mega-capable species or one confirmed holding a different item, a
plain toggle for an unambiguous form (revealing the item when it marks
Mega, since declaring Mega IS revealing the stone), and an X/Y/Z picker
for real ambiguity. The player's own roster only
shows the control when already holding its own real Mega Stone, since
a player's held item is always known up front. Both sides now swap the
roster tile's sprite via the existing `useMegaSprite` hook, and the
summary names the specific form via `formatMegaLabel`. Live-verified
again via `run-desktop` against real team data (`Mence Balance`'s
Salamence): gating correctly showed the control on only the one
stone-holding team member, the X/Y picker resolved correctly for a
test Charizard, and marking a second opponent Mega correctly cleared
the first through to the persisted summary. See commit 191bd70. Second
follow-up the same day: that pass still collapsed a multi-form species'
picker to a plain toggle the moment its item was set (including right
after the picker itself set it), leaving no way to fix a misclick (e.g.
Raichu X tapped instead of Y) short of removing and re-adding the
opponent Pokemon - confirmed live. A multi-form species now always gets
the full picker, never collapses, with the currently-chosen option
highlighted; the component's own switch-handling code already supported
this, only the gating function needed to change. Live-verified via
`run-desktop`: picked Charizard X, confirmed the picker was still there,
then switched to Y and confirmed the highlight moved. See commit
2eed364.
