# Completed work: 2026-10-23 to 2026-10-23

Archived from `COMPLETED.md` at the 2026-10-23 Type Matchup Rework
milestone boundary (the milestone's three legs, all shipped the same day).
See `docs/postmortems/type-matchup-rework.md`.

**[Type Matchup Rework] — Leg 1** (2026-10-23): Graded `CoverageCell.tsx`'s
coverage cells by magnitude instead of one flat color per favorable/
unfavorable side: green/blue for mild/extreme favorable, orange/red for
mild/extreme unfavorable, with immune staying a neutral gray badge
regardless of direction. Also recolored `CoverageTable.tsx`'s aggregate
Weak/Resist and Not Very Effective/Super Effective count badges to
threshold-color by count (0 / 1-2 / 3+) after live feedback flagged they'd
been missed in the first pass. Manually verified live in the running app
across two feedback rounds (color distinction, then threshold boundaries).
See commit 2878045.

**[Type Matchup Rework] — Leg 2** (2026-10-23): Removed the Team Gap
Analysis panel (`UsageThreatsList.tsx`, `usageThreats.ts`,
`usageCoverageGaps.ts`, and their tests) outright - no replacement panel.
`slotResistsThreat` moved into `typeCoverage.ts` (alongside
`getDefensiveMultiplier`) since `SpeedTiersPage.tsx`'s "Threats Only"
checkbox still depends on it; its tests moved there too. A first pass added
a replacement "Coverage Gaps" panel re-surfacing `computeDefensiveCoverage`'s
`unfavorableCount`/`favorableCount` per type, live-rejected same leg as
redundant - the Defensive `CoverageTable` already shows those exact counts
in its own Weak/Resist columns. Manually verified live in the running app:
Team Gap Analysis panel gone, no residual replacement panel, page shows
only the two `CoverageTable`s. See commit b506506.

**[Type Matchup Rework] — Leg 3** (2026-10-23): Wired the Mega/Alt-Form
toggle (`usePokemonFormToggle`) into both coverage tables via a new
`useActiveFormsForIds` (subscribes to several roster slots' toggle state at
once, since Rules of Hooks forbids calling the single-id hook inside a
dynamic `team.pokemon.map()`). A code-review pass flagged the "is this
toggle pointing at its own held Mega Stone" check as duplicated across
`EditablePokemonCore.tsx`, `useTeamMoveTypes.ts`, and `TypeMatchupPage.tsx`,
and the defensive-slot Mega-type resolution as untestable inline component
logic - both fixed by factoring into shared, tested pure functions
(`megaEvolution.ts`'s `resolveActiveMegaSlug`, `megaAbilities.ts`'s
`resolveActiveAbility`, `typeCoverage.ts`'s `resolveDefensiveSlot`), also
adopted by `EditablePokemonCore.tsx`'s existing Mega Team Card Flip logic.
Live-verified via the `run-desktop` driver with a disposable Mega Pinsir
team (Aerilate, Bug -> Bug/Flying): toggling Mega on shifted every expected
Offensive and Defensive cell to its mathematically correct value (e.g.
Ghost immune -> neutral, Rock 2x -> 4x, Ground resist -> immune), and
toggling off reverted every cell to the exact baseline. A follow-up
`/leg-review` (run by the user after an earlier mis-step where
`code-review --high` was silently substituted for it) caught a real latent
bug: `useTeamMoveTypes`'s new `activeForms` parameter defaulted to a fresh
`{}` literal, which would never stabilize across renders for any caller
that omitted it, spinning its fetch effect forever (reproduced at 14,514
`getMoveData` calls in ~160ms; not reachable today since the only call
site always passes a memoized value, but the hook is exported). Fixed with
a shared `EMPTY_ACTIVE_FORMS` constant default plus a regression test,
alongside five stale "see TODO.md" cross-references the same review caught
(TODO.md's entry collapsed to a Done-When summary once the milestone
closed; repointed to COMPLETED.md). See commits 33ef822 and d8a85a1.
